## Как пересобрать после правок

Факты зашиты в скрипты, поэтому ручные правки в docx при пересборке теряются: либо правьте docx вручную и больше не пересобирайте, либо вносите факты в скрипты.

- `facts.py` — карточка проекта (реквизиты, договор, тема, работы календарного плана), закупки, рецептуры, партии, сайт, реклама;
- `apx.py` — реестр приложений и объектов в них (номера «1А», «2Б» берутся отсюда и в отчёте, и в приложениях);
- `build_report.py`, `build_appendices.py`, `build_bp.py`, `build_dev.py` — тексты документов;
- `fin_model.py` — финансовая модель бизнес-плана;
- `dx.py` — оформление (профили report / app / bp / dev / fin);
- `build_fin.py` — финансовый отчёт и НДФЛ по CSV-выписке банка;
- `check_docs.py` — проверки, `list_utochnit.py` — список меток.

Фотографии и скриншоты для приложений можно не вставлять в Word вручную, а положить в `build/photos/` с именем ключа объекта (`ph_process`, `ph_batch2`, `ph_batch3`, `ph_pack`, `ph_site_main`, `ph_site_palette`, `ph_site_form`, `ph_site_metrika`, `ph_syn_card`, `ph_direct`, `ph_syn_metrika`, `ph_billboard1`, `ph_billboard2`, `ph_release`; расширение `.jpg`, `.jpeg` или `.png`) — скрипт вставит их вместо заглушек.

Нужны python3, python-docx, lxml, pdfplumber, Pillow, matplotlib и LibreOffice (содержание заполняется по страницам PDF, сборка в несколько проходов; сборки запускать по очереди, не параллельно):

```bash
cd build
python3 -I build_report.py
python3 -I build_appendices.py
python3 -I build_bp.py
python3 -I build_dev.py
python3 -I check_docs.py --report "out/Отчет_о_выполнении_работ_этап_2.docx" "out/Приложения_к_отчету_этап_2.docx"
python3 -I check_docs.py "out/Бизнес-план.docx::17" "out/Отчет_о_развитии_проекта.docx"
python3 -I list_utochnit.py out
```

Результат — в `build/out/`.

## Что проверяется автоматически

Для отчёта о выполнении работ и приложений (`check_docs.py --report`):

- поля, интервал 1,15 у каждого абзаца, абзацный отступ 1,25 см, выравнивание по ширине и по центру, отсутствие полужирного и курсива, Times New Roman 12 в каждом прогоне текста и в колонтитуле;
- номер страницы внизу по центру, первая страница файла имеет номер 2, объём с титульным листом не больше 20 страниц;
- содержание совпадает с заголовками в тексте и со страницами PDF; заголовков вне содержания нет; число страниц в реферате актуально;
- подразделы 1.1–1.5 и названия приложений совпадают с работами календарного плана из `facts.py`, тема приведена дословно;
- в подразделе 1.4 есть гиперссылка на сайт проекта;
- каждый объект приложений упомянут в отчёте, каждая ссылка отчёта ведёт на существующий объект, приложения упоминаются в порядке А–Д, объекты внутри приложения пронумерованы подряд;
- недопустимые формулировки, упоминания первого этапа, метки `[УТОЧНИТЬ]`, порядок элементов OOXML, источники пронумерованы в порядке упоминания и все процитированы.

Для бизнес-плана и отчёта о развитии — недопустимые формулировки, нумерация и ссылки на таблицы и рисунки, цитирование источников, порядок элементов OOXML.

Вёрстка проверялась в LibreOffice; в Word разбиение на страницы может отличаться на одну-две строки, поэтому каждый подраздел отчёта начинается с новой страницы, а последняя страница каждого подраздела заполнена не более чем на 81 %.
